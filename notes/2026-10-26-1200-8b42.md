# Multi agent orchestration

COORDINATOR gets the task

SUBAGENTS split it up

HUB AND SPOKE &gt; COORDINATOR gives out tasks, SUBAGENTS run with each one



One hub gives 3 advantages:

- Observability
- Consistent error handling
- Controlled information flow



CRITICAL ISOLATION PRINCIPLE

Subagents don't get the coordinator's context or conversation history

A new subagent only starts with what its given

No access to:

- coordinator's system prompt
- previous messages in the chat
- results from other subagents
- any shared memory

Subagents also don't carry memory from one
