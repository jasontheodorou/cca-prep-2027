# Multi agent orchestration

COORDINATOR gets the task

SUBAGENTS split it up

HUB AND SPOKE &gt; COORDINATOR gives out tasks, SUBAGENTS run with each one



One hub gives 3 advantages:

- Observability
- Consistent error handling
- Controlled information flow



CRITICAL ISOLATION PRINCIPLE

Subagents don't get the coordinator's context or conversation history

A new subagent only starts with what its given

No access to:

- coordinator's system prompt
- previous messages in the chat
- results from other subagents
- any shared memory

Subagents also don't carry memory from one call or prompt - all has to start over

They are essentially mindless automatons

EXAM TRAP 

Don't blame the subagent for a failure in the system before you check the coordinator



COORDINATOR JOB

It has 4 jobs:

- dynamically selecting subagents
- breaking up the research tasks into smaller pieces (research scope partitioning)
- looking at the output for gaps, then re-running it (iterative refinement loops)
- all subagent comms go through the coordinator for monitoring and information flow (centralised communication routing)

NARROW DECOMPOSITION FAILURE  

Poor task sharing (decomposition) leads to things being missed and topics not assigned.

Web search and synthesis can happen with many topics being skipped altogether.

The fault comes down to a bad coordinator, Jocko rules. 

Trying to fix subagent behaviour will not address the root issue at all.



EXAM TRAP 

The exam leans HARD on this misunderstanding.
